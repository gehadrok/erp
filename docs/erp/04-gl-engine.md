# 4. دليل الحسابات ومحرك القيود

## 4.1 دليل الحسابات

### البنية
- شجرة من مجموعات (levels) وحسابات أوراق. لا يُرحّل إلا إلى حساب ورقة (`is_leaf`).
- كل حساب له: `type` (أصول/التزامات/حقوق ملكية/إيرادات/مصروفات) و`normal_side` (D/C).
- حسابات مساعدة: كل مورد/عميل/صندوق/بنك/موظف/أصل قد يولّد حساباً مرتبطاً عبر `account_links`.

### القواعد
- تعديل الشجرة (دمج/حذف) مسموح فقط لحساب بلا حركة، أو بنهاية السنة مع إعادة تصنيف الأرصدة.
- تفعيل "مجموعات" مطابقة لإخراج القوائم المالية جاهزة (قائمة الدخل تقرأ من مجموعات محددة).

## 4.2 محرك القيود

### دورة حياة القيد
```
DRAFT ──اعتماد──► APPROVED ──ترحيل──► POSTED ──عكس──► REVERSED
   │                  │
   └── حذف/تعديل      └── يُعدل فقط بقيود عكسية/تعديلية
```

- **DRAFT**: قابل للتعديل والحذف من صاحبه.
- **APPROVED**: مراجع له صلاحية الاعتماد، لا يعدل الأطراف بل يعتمد أو يرفض مع ملاحظات.
- **POSTED**: أرصدة الحسابات تتأثر. لا يُعدل ولا يُحذف. التصحيح بـ:
  - قيد عكسي كامل (مبالغ معكوسة، نفس الأطراف) مرتبط بـ `reversed_by`، أو
  - قيد تعديلي جديد.
- **فترة مغلقة**: رفض أي ترحيل/عكس بتاريخ داخل فترة `CLOSED` أو `SOFT_CLOSED`.

### الخدمة الأساسية (واجهات منطقية)

```ts
// واجهات منطقية - لغة التنفيذ حسب 02-architecture.md
interface JournalEntryService {
  create(dto: CreateEntryDto): JournalEntry;   // يتحقق من التوازن، يولّد رقم القيد
  approve(id, approverId): void;
  post(id, userId): void;                      // داخل معاملة: UPDATE balances + status=POSTED
  reverse(id, userId, reason): JournalEntry;   // ينشئ قيداً معكوساً مرتبطاً
  getById(id): JournalEntry;
  list(filter): Paged<JournalEntry>;
}

// التوليد الآلي من مستندات
interface DocumentPostingRules {
  // كل وحدة (مبيعات/مشتريات/مخزون/رواتب/أصول) تسجل "قواعد ترحيل" باسم القاعدة
  // e.g. SALE_INVOICE: { debit: AR(customer), credit: REVENUE + OUTPUT_VAT }
}
```

### قواعد ترحيل المستندات (Posting Rules)

| المستند | مدين | دائن |
|---------|------|------|
| فاتورة بيع | العملاء (بالصافي + الضريبة) | إيرادات المبيعات (بالصافي) + ض.ق.م مخرجات (بالضريبة) |
| مرتجع بيع | إيرادات المبيعات + ض.ق.م مخرجات | العملاء |
| فاتورة شراء بضاعة | المخزون + ض.ق.م مدخلات | الموردون |
| فاتورة شراء (أصل/مصروف) | الأصل/حساب المصروف + ض.ق.م مدخلات | الموردون |
| مرتجع شراء | الموردون | المخزون (بالتكلفة) + ض.ق.م مدخلات |
| سند صرف لمورد | الموردون | النقدية/البنك |
| سند قبض من عميل | النقدية/البنك | العملاء |
| رواتب مسير | رواتب وأجور | رواتب مستحقة / تأمينات / سلف |
| صرف راتب | رواتب مستحقة | النقدية/البنك |
| إهلاك شهري | مصروف إهلاك | مجمع الإهلاك |
| تسوية جرد (نقص) | عجز/زيادة مخزون (مصروف/إيراد) | المخزون |
| فروق عملة (تصفية) | فروق صرف (خسارة) أو العكس | فروق صرف (ربح) |

### فروق العملة وتصفية الذمم

- كل قيد بعملة أجنبية يُحفظ بالعملة الأصلية + المبلغ المحوّل بالأساسي.
- عند تحصيل/سداد ذمم بعبر عملة مختلفة أو بسعر صرف جديد: احسب الفرق (`realized FX gain/loss`) وسجّله على حساب فروق الصرف.
- عند الإقفال السنوي: تُعاد تقييم الأرصدة الأجنبية المفتوحة بسعر نهاية الفترة (unrealized) بقيد تعديلي.

### الإقفال الشهري/السنوي

1. تسوية الجرد النهائي (تحقق تطابق دفتر المخزون مع الفعلي).
2. إعادة تقييم العملات.
3. قيد الإهلاك الشهري.
4. ترحيل الإيرادات/المصروفات إلى "مجمل الربح/الخسارة" (قيد إقفال سنوي فقط).
5. غلق الفترة (`CLOSED`) — يمنع الترحيل، وفتحها يتطلب صلاحية خاصة ويسجَّل في التدقيق.
