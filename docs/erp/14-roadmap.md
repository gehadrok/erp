# 14. خطة التنفيذ والمراحل

## 14.1 مراحل البناء

### المرحلة 0 — التأسيس (2–3 أسابيع)
- تهيئة المستودع، بيئات dev/staging، CI/CD، قالب المشروع.
- وحدة Core: شركات، فروع، عملات، ترقيم، مستخدمون ومصادقة، سجل تدقيق.
- **المخرج:** دخول مستخدم، إنشاء شركة وفروع، ترقيم يعمل.

### المرحلة 1 — قلب النظام المحاسبي (4–6 أسابيع)
- دليل الحسابات (شجرة + حسابات مساعدة + حسابات افتراضية).
- محرك القيود كاملاً (مسودة/اعتماد/ترحيل/عكس، فترات مالية وإقفال).
- أرصدة مجمّعة + كشف حساب + ميزان مراجعة.
- **المخرج:** قيود يدوية متوازنة تُرحّل وتظهر في التقارير. *هذه أهم بوابة جودة في المشروع.*

### المرحلة 2 — المخازن والمشتريات (4–5 أسابيع)
- أصناف ومستودعات وحركات (إضافة/صرف/تحويل/جرد) بطريقتي التكلفة.
- موردون، أوامر شراء، فواتير شراء بـ 3-way matching، سندات صرف.
- **المخرج:** دورة شراء كاملة تنتج حركة مخزنية وقيوداً صحيحة.

### المرحلة 3 — المبيعات والتحصيل (4–5 أسابيع)
- عملاء، عروض أسعار، فواتير بيع مع COGS، مرتجعات، سندات قبض، حد ائتماني.
- تقارير أعمار الذمم والمبيعات.
- **المخرج:** دورة بيع كاملة: عرض سعر → فاتورة → تحصيل، بقيود متوازنة.

### المرحلة 4 — الضرائب والفاتورة الإلكترونية (3–4 أسابيع)
- إقرار VAT، توليد XML، التوقيع، الربط ببيئة ZATCA التجريبية ثم الإنتاج.
- **المخرج:** فاتورة ضريبية Clear + مبسطة Report من بيئة الاختبار.

### المرحلة 5 — الرواتب والأصول (4–6 أسابيع)
- مسير رواتب كامل بمحاسبة صحيحة؛ أصول ثابتة وإهلاك شهري آلي.
- **المخرج:** مسير شهر مُرحّل وقيد إهلاك آلي.

### المرحلة 6 — التقارير المتقدمة والتشغيل (مستمر)
- قائمة الدخل/المركز المالي/التدفقات، مصمم تقارير JSON، جدولة وإرسال.
- تحسينات أداء، لوحة مؤشرات، تدريب المستخدمين.

**الإجمالي التقريبي: 5–7 أشهر لفريق 3–5 أشخاص.**

## 14.2 الفريق

| الدور | العدد | ملاحظات |
|-------|-------|---------|
| قائد فني/معماري | 1 | يملك محرك القيود شخصياً |
| Backend | 2 | وحدات الأعمال |
| Frontend | 1–2 | شاشات كثيفة إدخال بيانات — أولوية UX |
| محاسب نظام (Domain Expert) | 1 | يحدد القواعد ويختبر المخرجات — لا غنى عنه |
| QA | 1 | سيناريوهات محاسبية مكتوبة |

> **تحذير:** أكبر سبب لفشل أنظمة ERP هو غياب الخبير المحاسبي أثناء التطوير، واكتشاف أخطاء الأرصدة بعد الإقفال.

## 14.3 البيانات الافتتاحية

1. دليل حسابات العميل + الأرصدة الافتتاحية (قيد افتتاحي واحد متوازن).
2. أرصدة مخزون افتتاحية (صنف/مستودع/كمية/تكلفة) — بلا قيد مخزون منفصل إن كان القيد الافتتاحي شاملها.
3. أرصدة عملاء وموردين بتواريخ فواتيرهم (لأعمار الديون) + سلف موظفين.
4. أصول ثابتة بتكلفة ومجمع إهلاك سابق.
5. أدوات استيراد Excel موثقة + تقارير تحقق (مجموع الاستيراد = القيد الافتتاحي).

## 14.4 المخاطر وتخفيفها

| الخطر | الأثر | التخفيف |
|-------|-------|---------|
| أخطاء تكلفة/قيود تُكتشف متأخراً | مرتفع | اختبارات محاسبية ذهبية + تسويات تجريبية شهرية قبل الإنتاج |
| تغيّر متطلبات الفاتورة الإلكترونية | متوسط | عزل وحدة einvoice + متابعة التحديثات |
| إدخال بيانات بطيء (إنتاجية منخفضة) | متوسط | تصميم شاشات كيبورد-أولاً، باركود، استيراد |
| أداء التقارير على بيانات كبيرة | متوسط | أرصدة مجمّعة + replica قراءة |
| اعتماد المستخدمين ضعيف | مرتفع | إشراك المحاسبين مبكراً، تدريب، فترة تشغيل متوازي |

## 14.5 التشغيل المتوازي والانتقال

- شهر على الأقل: النظام القديم والجديد يعملان معاً على نفس المستندات، ومطابقة أرصدة يومية/أسبوعية.
- بوابة الإقفال: مطابقة كاملة لميزان المراجعة وقائمة الدخل بين النظامين لنهاية الشهر.
- خطة تراجع: النظام القديم يبقى قابلاً للتشغيل لمدة 3 أشهر بعد الانتقال.

## 14.6 تعريف الإنجاز (Definition of Done) لكل وحدة

- [ ] الوظيفة تعمل مع فحص صلاحيات وسجل تدقيق.
- [ ] قيود المستندات متوازنة ومطابقة لجدول قواعد الترحيل (اختبار آلي).
- [ ] تقارير الوحدة صحيحة على بيانات تجريبية معروفة النتائج.
- [ ] توثيق API محدث + دليل مستخدم مختصر للشاشة.
- [ ] مراجعة محاسبية موقعة من خبير المجال.
